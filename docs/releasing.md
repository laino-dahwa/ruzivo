# Releasing the desktop app

## Versioning

`package.json`'s `version` field is the single source of truth. `app.getVersion()` reads it automatically once electron-builder bundles the app — there is no separate Electron version file to keep in sync. The installer filename (`Ruzivo-Setup-<version>.exe`) and the GitHub Release tag are both derived from it too.

## CI

- **`.github/workflows/test.yml`** — every push/PR to `main`: `npm run migrate` (against a `postgres:17` service container), `npm run lint`, `npm run typecheck`, `npm test`.
- **`.github/workflows/build.yml`** — every push/PR: `npm run electron:build:prod` then `electron-builder --dir --win` (packages, doesn't publish). Catches packaging breakage on every change, not just at release time.
- **`.github/workflows/release.yml`** — triggered by pushing a `vX.Y.Z` tag. Re-runs the full gate (migrate/lint/typecheck/test/build) as sequential steps in one job before publishing, so a release can only happen once everything has genuinely passed on the exact tagged commit. First verifies the tag matches `package.json`'s version and fails with an annotated error otherwise.

## Cutting a release

1. Bump `version` in `package.json`.
2. Commit it.
3. Tag and push:
   ```bash
   git tag v0.2.0
   git push origin v0.2.0
   ```
4. `release.yml` runs the full gate, then `electron-builder --win --publish always`, which uploads the installer, its `.blockmap`, and `latest.yml` to a new GitHub Release for that tag.

`GITHUB_TOKEN` needs `contents: write` for the publish step to create the release and upload assets — already granted via the workflow's `permissions:` block, since many repos now default that token to read-only.

## Auto-update

`electron-updater` (GitHub Releases provider, configured in `electron-builder.yml`'s `publish:` block) checks for a newer tag automatically ~5s after the main window loads, using `app-update.yml` (generated by electron-builder only for the real `nsis` build target, not `--dir`). On finding one, it downloads in the background and the renderer (`components/layout/update-notice.tsx`) shows a "Restart now" toast once the download completes.

**Update installs are locked out during migrations/backups**: `electron/updater.ts#quitAndInstallUpdate` refuses to fire while `electron/main.ts`'s `isMigratingOrBackingUp` flag is set, so the app can never restart into an update mid-migration or mid-backup.

## Manual installer upgrade

Running a newer `Ruzivo-Setup-<version>.exe` by hand over an existing install works the same way as auto-update, data-safety-wise: NSIS's default behavior already preserves `userData` (config, embedded Postgres data, backups — all outside the install directory) and upgrades the installed files in place. No custom uninstall/reinstall logic was needed. The same startup-sequence migration check in `electron/main.ts` runs regardless of how the new version got installed, bringing the schema forward from whatever version was there before.

## Unsigned installer

The installer is unsigned for now — Windows SmartScreen shows a one-time "unknown publisher" warning on first run. Auto-update itself works unsigned. Adding a certificate later is a drop-in change (a secret + one `electron-builder.yml` config line), not a rearchitecture.
